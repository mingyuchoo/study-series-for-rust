## 1. 제품 요약

### 1.1 한 줄 정의

**go-ai-bridge**는 기업 레거시 시스템(ERP, CRM, 그룹웨어, DB, 파일, 메인프레임 등)과 LLM 기반 AI 에이전트 사이에 위치하는 **통제형 실행 게이트웨이** 상용 제품이다.

LLM이 레거시 자원을 직접 호출하지 못하게 차단하고, 허용된 업무 도구만 **정책·승인·스키마·감사·워크플로** 파이프라인을 통과한 뒤 집행한다.

### 1.2 구매 가치 제안 (Why Buy)

| 구매 동기 | 제품이 제공하는 결과 | 영업 메시지 |
| --- | --- | --- |
| AI 도입 시 레거시 유출·오남용 위험 | LLM–레거시 사이 방화벽·번역·통제 계층 | “AI를 켜도 ERP를 직접 열지 않습니다” |
| 통제 단위 부재 | 도구 allowlist, L1~L4, RBAC+ABAC | “시스템 권한이 아니라 업무 도구 단위로 통제” |
| 감사·컴플라이언스 공백 | append-only 감사, 해시 체인, 보존·SIEM | “누가·무엇을·왜 실행했는지 재구성 가능” |
| 고위험 자동화 실패 | 승인, dry-run, TTL, 보상 워크플로 | “환불·발주도 사람 승인 없이 못 나갑니다” |
| 프로토콜 파편화 | REST/SOAP/DB/File 어댑터 + MCP/OpenAPI | “레거시를 바꾸지 않고 AI에 안전하게 노출” |
| 운영 가시성 부족 | 콘솔, OTel, 거부·인젝션·비용 신호 | “보안·운영이 같은 화면에서 감시” |

### 1.3 제품이 아닌 것 (Non-Goals)

| 제외 범위 | 이유 |
| --- | --- |
| 범용 LLM 채팅 SaaS | 본 제품은 **집행·통제 계층**에 집중. UI는 채널 연동 대상 |
| 임의 SQL/쉘/URL 실행 플랫폼 | 보안 모델과 정면 충돌 — **판매 기능으로 제공 금지** |
| 레거시 시스템 자체 교체 | 기존 ERP/CRM을 대체하지 않고 안전하게 노출 |
| 모델 학습/파인튜닝 플랫폼 | 모델 공급은 외부(Azure OpenAI 등)에 위임 |
| 기본 제공 완전 무인 고위험 자동화 | L4는 기본 차단, 고객 보안 심사 후 명시 허용 |

### 1.4 포지셔닝

> 레거시와 AI를 잇는 계층은 “LLM용 API 어댑터”가 아니라  
> **권한·정책·도구·워크플로·감사·보안을 통합한 Enterprise Agent Gateway**여야 한다.

**경쟁 대비 차별점 (판매 시 강조):**

1. **단일 집행 경로** — 도구 호출이 정책을 우회할 경로 없음  
2. **위험 등급 승인 모델** — 읽기/쓰기 2분법이 아닌 L1~L4  
3. **감사 무결성** — append-only + 해시 체인 (변조 검출)  
4. **워크플로 멱등·보상** — 고위험 다단계 업무를 상태 머신으로 고정  
5. **MCP 네이티브** — 기존 AI 클라이언트와 즉시 연동  
6. **데이터 상주** — 온프레미스/VPC 설치로 규제 고객 대응

## 2. 문제·시장·고객

### 2.1 문제

기업이 LLM 에이전트를 내부 시스템에 연결할 때:

1. **과도한 권한(Excessive Agency)** — 직접 ERP/DB 접근 시 인젝션 한 번으로 대량 조회·변경  
2. **통제 단위 부재** — “ERP 접근 권한”이 업무 경계와 불일치  
3. **읽기/쓰기 혼재** — 조회와 환불·발주가 동일 경로  
4. **감사 불가** — 프롬프트·도구·결과 재구성 실패  
5. **레거시 이질성** — SOAP, REST, DB, 배치, RPA, 메인프레임 혼재  
6. **운영 실패 전파** — 느린 레거시가 에이전트 전체 정지·중복 쓰기  

위협 모델 정렬: OWASP LLM Top 10, NIST AI RMF / Generative AI Profile.

### 2.2 해결 원칙 (제품 불변식)

| ID | 원칙 | 제품 함의 |
| --- | --- | --- |
| P1 | LLM은 판단, 게이트웨이는 집행 | 모델은 tool call만 제안 |
| P2 | 시스템 권한이 아닌 업무 도구 노출 | allowlist + JSON Schema |
| P3 | 위험 등급으로 승인·차단 | L1~L4 |
| P4 | 허용뿐 아니라 결과 축소 | obligations (mask/redact/max_rows) |
| P5 | 관측과 통제 분리 | 인젝션 휴리스틱은 기본 “표시” |
| P6 | 실패는 fail-closed | 신원·승인 저장소 장애 시 실행 중단 |
| P7 | 고위험은 상태 머신 | 멱등·lease·보상 |

### 2.3 대상 고객·페르소나

| 세그먼트 | 구매 트리거 | 주 의사결정자 |
| --- | --- | --- |
| 중견~대기업 내부 IT | 사내 AI 포털/봇 보안 심사 | CISO, 아키텍트 |
| 금융·공공·헬스케어 | 규제·감사 보존 게이트 | 컴플라이언스, 보안 |
| SI/컨설팅 파트너 | 반복 납품 가능한 미들웨어 | 사업 리더, 아키텍트 |
| 플랫폼/ISV | 에이전트에 엔터프라이즈 통제 OEM | 제품 책임자 |

| 페르소나 | 성공 기준 |
| --- | --- |
| CISO | 권한 위반 0, 감사 추적, L4 기본 차단 |

## 3. 제품 아키텍처 요구

### 3.1 논리 아키텍처

```
[Channel Layer]
  웹 채팅 · CLI · Slack/Teams · 사내 포털 · Claude Code/Desktop 등 MCP 클라이언트
        │
        ▼
[Agent Layer]  (제품 동봉 또는 고객 오케스트레이터)
  LLM Orchestrator · Intent Router · Conversation Memory · Response Generator
  (_meta: prompt / tokens / cost)
        │  MCP Tools + 신원(헤더/Bearer)
        ▼
[AI Integration Gateway]  ★ 제품 핵심 (판매 SKU의 중심)
  Identity Resolver · Context Enricher
  Tool Registry · Policy Engine · Schema Validator
  PII Masker · Injection Detector · Rate Limiter · Budget
  Approval Manager · Audit Logger (해시 체인)
        │
        ▼
[Context Layer]
  RAG / Document Store / Metadata Index
        │
        ▼
[Workflow Layer]
  State Machine · Lease/Fencing · Retry · Compensation · Human Approval
        │
        ▼
[Legacy Adapter Layer]
  ERP · CRM · Ticket · Docs · Purchase · Refund · (확장 어댑터)
  Transport: REST · SOAP · DB · File · (RPA/Mainframe 확장)
        │
        ▼
[Legacy Systems]
  ERP / CRM / 그룹웨어 / 회계 / 인사 / 메인프레임 / 파일서버 / 사내 API
```

### 3.2 강제 실행 파이프라인 (모든 도구 호출, 우회 불가)

| 단계 | 요구 | 실패 시 |
| --- | --- | --- |
| 1 | 레이트 리밋 · 세션 비용 상한 | 거부 (`budget_exceeded` 등) |
| 2 | 도구 allowlist 조회 | 미등록 도구 거부 |
| 3 | 입력 JSON Schema 검증 | 거부 |
| 4 | 신원 해석 + 환경 속성 enrich | 신원 불가 시 거부 (익명 강등 금지) |
| 5 | RBAC + ABAC + 에이전트 스코프 | 거부 / 승인 요구 / obligations |
| 6 | 위험 등급 관문 (L3 승인, L4 기본 차단) | dry-run 또는 차단 |
| 7 | 어댑터 실행 (타임아웃·재시도·서킷 브레이커) | 표준 오류 코드 |
| 8 | 출력 스키마 검증 | `invalid_output` |
| 9 | 정책 obligations 집행 | 축소된 출력 |
| 10 | PII 마스킹 | 마스킹된 출력 |
| 11 | 프롬프트 인젝션 탐지(표시) | 감사 표시 (기본 비차단) |
| 12 | 감사 로그 append-only | 실패 시 fail-closed 권장 |

### 3.3 금지 경로 (제품·계약상 제공 금지)

```
금지: LLM → DB 직접 쿼리
금지: LLM → 레거시 API 직접 호출
금지: LLM 생성 SQL / URL / 쉘 명령 실행
금지: LLM이 임의 파일 경로 지정 실행
금지: LLM이 권한 정책을 자체 해석·우회
금지: 승인 없이 L3+ 쓰기 집행
금지: 미등록 도구·스키마 없는 도구 등록
금지: 운영 모드에서 mock 백엔드를 기본 허용
```

우선순위: **P0** = GA/판매 필수 · **P1** = Standard 권장 · **P2** = Enterprise/로드맵

### 4.1 도구 레지스트리 (Tool Registry)

| ID | 요구사항 | 우선순위 | 인수 기준 |

## 6. 데이터 흐름 (표준 유스케이스)

### 6.1 조회·요약 (L1)

1. 채널 인증 → 주체 해석·enrich  
2. 에이전트 의도 → tool call  
3. 게이트웨이: 리밋 → allowlist → 스키마 → 정책 → 실행  
4. Adapter 조회 → obligations + PII  
5. 에이전트 요약 (근거 포함)  
6. 감사 기록  

**불변:** LLM은 ERP를 직접 조회하지 않는다.

### 6.2 승인형 실행 (L3)

1. L3 tool call → 승인 요청 + dry-run (미실행)  
2. 관리자 승인/거부 (self-approve 불가)  
3. 동일 인자·TTL 내 1회 실행  
4. 감사에 요청·결정·실행 연결  

### 6.3 고위험 워크플로 (L4)

1. L4 enable + 승인 후에만 진입  
2. 조회 → 조건 → 계산 → 초안 → 집행 → 알림  
3. 영속화·멱등·보상  
4. 실패 시 운영자 복구

## 15. 제약·가정·리스크

### 15.1 가정

- 사람 사용자는 신뢰 가능한 인증 프록시/IdP 뒤에 둔다.  
- 레거시가 멱등 키·fencing을 존중해야 E2E 중복 방지가 완성된다.  
- LLM 품질은 모델 공급자에 의존; 제품은 근거·스키마·정책으로 완화한다.  
- 초기 상용은 **고객당 전용 배포**를 기본으로 한다.

## 17. 최종 제품 요구 (한 줄)

**go-ai-bridge는 LLM이 레거시를 직접 만지지 못하게 하는 엔터프라이즈 Agent Gateway 상용 제품으로, 도구 레지스트리·정책·승인·스키마·PII·감사·워크플로·관측을 단일 집행 경로에 통합하고, GA 품질 게이트·에디션 패키징·설치/문서/지원 SLA를 갖춰 파일럿에서 유료 운영으로 전환 가능한 판매 제품이어야 한다.**
